# Workflow

The workflow is artifact-driven, not plugin-state-driven.

## Standard Path

1. Fill `PROJECT_CONTEXT.md`.
2. Build `storyline.md`.
3. Organize `references/`.
4. Draft `paper.md` section by section.
5. Review changed sections into `reviews/`.
6. Revise from review reports.
7. Run submission precheck.
8. Put final deliverables in `outputs/`.

## Re-entry

Any stage can be repeated. For example, a failed evaluation review may send the project back to `storyline.md` or `PROJECT_CONTEXT.md` to narrow claims.

## State

The current state is visible in files:

- missing facts in `PROJECT_CONTEXT.md`;
- unresolved logic in `storyline.md`;
- draft quality in `paper.md`;
- findings in `reviews/`;
- available evidence in `references/`, `notes/`, and `outputs/`.
